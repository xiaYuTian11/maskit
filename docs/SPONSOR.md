# 赞助入口：合规边界与实现说明

> 本文只记录「为什么这么做」，不写宣传话术。改动代码前请先读完第 1 节。

## 1. 必须分清的两件事

| 形态 | 用户付钱后得到什么 | 性质 | 合规结论 |
|---|---|---|---|
| **A. 纯赞助（当前已实现）** | 什么都不额外得到，功能一样 | 无偿赠与 | 可以。个人收款码收「赞赏」不算经营性收款 |
| **B. 赞助回赠激活码** | 得到一个解锁码（可开新功能） | 有对价 | 灰色偏险。被认定为「变相经营」的概率不低 |
| **C. 商户收款 + 明确售卖** | 购买许可 | 经营行为 | 必须用**商户号**收款并开票，个人码不行 |

关键法源：央行《关于加强支付受理终端及相关业务管理的通知》，**自 2022 年 3 月 1 日起，个人收款码不得用于经营性收款**。
所以「用个人微信/支付宝收款码 + 锁功能」这个组合**不能做**——不是道德问题，是收款账户可能被风控限制的问题。

## 2. 当前实现（形态 A）

- 组件：`frontend/src/components/common/SponsorDialog.tsx`
- 入口：`frontend/src/components/layout/AppLayout.tsx` 侧栏底部「赞助支持」
- 文案强调三点：自愿、不构成对价、不影响任何功能
- 图片资源：`frontend/public/sponsor/wechat.png`、`frontend/public/sponsor/alipay.png`
  - 已落地真实收款码（微信 653×633 / 支付宝 778×758，合计约 320KB，进仓库可接受）
  - 两张码中心都带各自头像，属于收款码自带样式；如需更"干净"的外观，可换成不带头像的官方码
  - 未放置时弹窗显示文字兜底，不出现破图
  - 建议尺寸：正方形 ≥ 600×600 PNG，白底

## 3. 若确实要做「解锁」（形态 B/C）的技术方案

### 3.1 不要做的事

- 不要在客户端做 license 判断后直接返回功能（`if (license) {...}` 在明文 Python/Tauri JS 里等于没有）
- 不要把解锁状态只存 `localStorage`（删一个键就破）
- 不要锁**已发布**的功能（AGPL 项目锁已有功能 = 社区定性为「假开源」，会丢 star 与贡献者）

### 3.2 推荐做法：只锁「新增页面」，用离线激活码

1. 新增页面（如 `/toolbox` 本地文件脱敏工作台）作为独立入口，社区版显示「未解锁」引导页
2. 激活码格式：`MASKIT1-<device8>-<expiryYYMMDD>-<hmac10>`
   - `device8`：设备码前 8 位（`sha256(机器指纹)[:8]`，不含任何可识别信息）
   - `hmac10`：`HMAC-SHA256(secret, "MASKIT1|device8|expiry")` 前 10 位
   - 前端用 WebCrypto `SubtleCrypto` 校验（Chromium 全平台可用）
3. **安全要诚实**：secret 内置在客户端，逆向可得。这套机制只能防「白嫖传播激活码」，不能防「有决心的人」。
   真正的防破解只有一个办法：**能力不下发**（服务端执行或需要联网授权）——这与「100% 本地」定位冲突，所以个人开发者不宜追求。
4. 授权状态存 `localStorage` 只是缓存，每次启动用激活码重算校验值，避免单点伪造。

### 3.3 交付节奏建议

- 先只上形态 A，跑 2~4 周看有多少人真的打赏（这是对「愿不愿付钱」最便宜的测量）
- 打赏转化若能到 star 数的 0.5% 以上，再讨论形态 C（注册个体户/小微商户 + 正规售卖）
- 形态 B 只在「明确标注为回赠、且不做售后承诺」时使用，并保留随时改为 A 的能力

## 3.4 提示时机（比提示次数更重要）

| 方式 | 结论 | 原因 |
|---|---|---|
| 每次开机弹窗 | ❌ 不做 | 直接打断当日工作，换来的通常是卸载与差评，不是打赏 |
| 每日弹一次 | ❌ 不做 | 每天提醒「你在薅我羊毛」，对 AGPL 口碑是净损失 |
| 首次启动就弹 | ❌ 不做 | 用户还没获益，此时提钱等于开局讨债 |
| **获益后按节奏轻提示** | ✅ 已实现 | 门槛：累计 MASK 事件 ≥ 300 **且首启满 7 天**；非模态，三个出口（支持 / 30 天后再说 / 不再提示） |
| **节奏：7 天后首次，之后每 30 天最多一次** | ✅ 已实现 | 只弹一次等于放弃长尾；每天弹等于扰民。30 天是一个「足够稀疏、又不至于被忘掉」的量级 |
| 顶栏常驻图标入口 | ✅ 已实现 | 零打扰，想给的人自己找得到（与 GitHub 图标同一行，不占新位置） |
| 顶栏图标「呼吸光」 | ✅ 已实现（**有生命周期**） | 玫瑰色静态 + 2.8s 呼吸；仅「首启 14 天内且没点开过」生效，点开一次或满 14 天永久退化静态；`prefers-reduced-motion` 只留静态色。常驻动画会把「被看见」变成「广告位」 |
| 统计页软文案 | ✅ 已实现 | 「已挡下 N 条」是由用户自己算出的获得感，此处转化最高，小字即可 |
| README 支持者名单 | ✅ 已实现 | 社会认同 > 提醒；只写昵称不写金额 |
| 版本更新说明里一行 | ❌ 不做（2026-11-23 作者决定） | 发版日志里不写赞助相关内容：读更新日志的人是来看「产品改了什么」，不是来看募捐的。方案保留在本文档，要做时在 `render()` 末尾拼一段即可 |

实现：`frontend/src/components/common/SponsorNudge.tsx`（右下角卡片）；状态 `localStorage.maskit_sponsor_nudge = {"off":bool,"nextAt":ms}`、首启时间 `maskit_first_seen_at`；出现即写 `nextAt = now + 30d`（用户即使不理会也不会反复打扰）。顶栏光效的状态键是 `maskit_sponsor_seen`（点开弹窗即写，后续永不呼吸），CSS 在 `frontend/src/index.css` 的 `.sponsor-heart`。
