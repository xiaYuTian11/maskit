# Data Maskit 设置说明

本文按面板中的页面和开关解释配置口径。首次使用建议先完成面板内引导，再按需阅读高级设置。

面板顶栏的「帮助」入口提供页面导览、快速上手路径和本文/完整教程的跳转；三步首次引导只在新装且尚未配置任何客户端时自动出现，之后可从「帮助」里点「重新打开首次引导」再次调出。

## 1. 最短使用路径

1. 在「客户端管理」添加上游服务，确认目标 Base URL、路径和本地端口。
2. 将 Cursor、CLI、SDK 等客户端的 Base URL 指向客户端卡片显示的本地地址，例如 `http://127.0.0.1:<端口>/v1`。
3. 在控制台启动代理并发送一条真实请求。
4. 到「拦截日志」确认请求有脱敏记录、响应有还原记录。

API Key 仍由客户端配置，Maskit 不要求把密钥填入面板说明或日志。关闭代理后是否直连，取决于「停止模式」和客户端自身行为；直连不等于脱敏保护。

## 2. 页面功能

| 页面 | 用途 |
| --- | --- |
| 控制台 | 查看代理状态、近期活动和运行概况。 |
| 拦截日志 | 查看脱敏、还原、放行、阻断和错误事件；详情可能受日志记录模式影响。 |
| 数据统计 | 查看请求量、脱敏量、还原量和模型用量统计。 |
| 客户端管理 | 配置上游服务与本地入口，测试端口、模型或聊天连通性。 |
| 浏览器扩展 | 配置网页 AI 桥接、扩展令牌和文档脱敏行为。 |
| 敏感词库 | 管理自定义词、内置规则、整词匹配和敏感词类别。 |
| 审计中心 | 查看提示词注入、响应投毒、凭据回显等安全审计信号。它不是请求脱敏开关。 |
| 高级设置 | 调整代理、日志、隐私、连接、安全和系统行为。 |

## 3. 高级设置

### 3.1 代理行为

- **启用请求脱敏**：扫描请求并替换敏感信息。关闭后请求不会按普通脱敏链路处理。
- **Fail-Closed**：脱敏管线异常时阻断请求，而不是把可能含明文的请求放行。安全场景建议保持开启。
- **响应扫描/还原**：处理模型响应中的占位符还原及响应侧扫描。
- **启动时自动启动代理**：引擎启动后自动启动代理监听。
- **NER 语义识别**：使用本地语义模型补充规则识别。需要本地模型和运行时支持，开启后应检查页面显示的可用状态。
- **严格要求语义检测完整**：语义检测不完整时阻断请求，安全性更高但可能增加等待和阻断；长会话尤其需要关注预算。
- **NER 单请求预算**：仅限制语义识别阶段的预算，不是模型生成或完整 SSE 响应时长。

### 3.2 停止模式

- **错误响应**：代理停止时返回错误，适合明确提醒客户端当前不可用。
- **明文直连**：代理停止时保持网络可用，但请求不会经过脱敏。除非明确接受直连风险，不建议用于含敏感信息的客户端。
- **阻断**：代理停止时直接拒绝请求，适合强制保护场景。

### 3.3 上游连接策略

- **连接复用**：控制 HTTP/1.1 上游连接是否复用。通常保留默认；禁用复用可能增加握手和延迟，不会自动关闭 HTTP/2。
- **空闲期限**：HTTP/1.1 空闲连接允许保留的秒数。留空表示不改变现有策略。
- **建连预算**：建立上游 TCP 连接的最长等待时间，不是整个模型请求超时。
- **TLS 预算**：完成 TLS 握手的最长等待时间，不是模型生成或 SSE 流时长限制。
- **接管上游连接（`upstreams[].takeover`）**：在「客户端管理」的客户端编辑页按上游单独开启，默认关闭，**只在反向代理模式下显示**（其它捕获模式下引擎不会调用接管通路，开关本身没有意义）。开启后该上游的连接由引擎进程级连接池持有并在多个客户端之间复用，不再每个请求重做一次 TCP+TLS 握手；关闭则回到原有的逐客户端连接路径。它只改变转发方式，不改变脱敏与还原的内容，也不新增出网目的地（仍是同一个 `target`，且 sidecar 只放行配置里声明过的目标）。

如果页面提示当前版本仅提供连接观测，则这些控制不会生效，不能根据输入框的值推断运行时已应用。

引擎侧另有一项**真正生效**的握手时间预算：环境变量 `MASKIT_CONNECT_STALL_S`（默认 20 秒，设 `0` 退回纯观测）。它只掐「请求尚未写向上游」时卡住的建连 / TLS 握手并回 502，与上面这几个输入框无关，也不给首包或 SSE 流设时长上限；口径与风险见 `SECURITY.md` 的环境变量表。

上游「连上了但不吐字节」由三条不同的时间线负责，面板没有输入框，不要指望在这里改：

- **响应流空闲闸（默认路径与接管路径都受管）**：环境变量 `MASKIT_SSE_IDLE_S`（默认 120 秒，设 `0` 退回纯观测）管的是**首包之后相邻两个数据块的间隔**——连续 120 秒一个字节都没收到，网关就取消这条客户端连接，记录落 `reason=upstream_idle`、责任方 `upstream`。刻意不按总时长设闸：本机库里存在 876 块 / 412 KB / 跑满 646 秒的合法长生成，按总时长一刀切就是砍真请求；首包之前的静默也一律不管，推理模型几分钟不出首包是合法的。要调这个数，向运行指标里的 `stream_idle.max_gap_s`（本机实测到的最大块间隔）要，不要拍。执行开关 `MASKIT_SSE_IDLE_KILL=0` 只观测不断链。
- **未接管（默认路径）**：只有空闲闸没落刀时（例如匹配不到唯一的那一个连接 task，或闸被关掉）才由 mitmproxy 自带的连接空闲看门狗兜底，默认 **600 秒**。这一项刻意不开放配置——它同时守着上游 keep-alive 的空闲连接，调低会把连接复用一起掐掉，而复用正是上面那个「接管上游连接」开关要保的东西。到点被掐时，网关取消的是客户端读任务，错误文案长得像「客户端断开」，因此这类记录会被改判为 `reason=upstream_idle`、责任方 `upstream`，意思是**该查上游和链路，不是催客户端别急**；拿不到「最后一次收到上游字节」的证据时仍照旧判 `client`，不做猜测。
- **已接管（`upstreams[].takeover`）**：由引擎侧连接池按 **120 秒间隔**超时处理（相邻两个数据块之间静默 120 秒即断），只作用于上游一侧，正常的长生成不受影响。

所以想让「卡住十几分钟」变成快速失败：默认路径靠上面第一条空闲闸（不必开启接管），开启接管则额外让上游侧自己也带上 120 秒间隔超时——两者都不是去调任何超时输入框。

### 3.4 日志与隐私

- **日志模式**：摘要模式减少本地记录；详细模式提供更多详情，适合排障。限时排障模式只应在必要时开启。
- **保留天数**：控制事件库的保留周期。缩短周期可减少本地数据留存。
- **记录明文敏感词**：会影响本地详情可见范围。安全审计和共享诊断包前应确认不会暴露原文。
- **诊断包**：仅在本地生成，发送前应先预览并人工检查；不要直接上传包含业务上下文的文件。

### 3.5 安全审计

- **被动审计**：对正常请求/响应产生安全信号，不主动发起探测请求。
- **主动探针**：会向配置的上游发起验证性请求，仅在明确需要时开启，并提前确认上游费用、权限和数据边界。
- **严重性阈值**：控制哪些级别进入展示或报告。
- **安全信号开关**：各信号只影响审计检测，不会替代请求脱敏规则。

## 4. 日志如何排障

1. 先确认控制台显示代理运行。
2. 在日志页暂时关闭「隐藏噪声」，避免遗漏取消、DNS 或透传记录。
3. 对 `ERR` 和 `BLOCK` 打开详情，重点看 `reason`、`failure_phase`、是否已上行以及连接观测。
4. `BLOCK` 通常表示请求被安全闸阻断；不要仅按 HTTP 状态码判断是否已发送到上游。

## 5. 常见问题

### 日志里没有请求
确认客户端 Base URL、端口、路径前缀与客户端卡片一致；确认代理正在运行；检查日志页的入口和类型筛选。

### 模型回答出现占位符
确认请求和响应都经过同一个本地入口，并检查是否存在会话切换、客户端绕过代理或还原失败事件。

### 请求被阻断
先看日志详情的阻断原因。请求体超限、引擎繁忙、脱敏超时、管线异常和严格语义检测不完整的处理方式不同，不要直接重复发送可能已由上游执行的请求。

### 浏览器扩展无法使用
确认扩展桥接已启用、面板地址正确、令牌已同步；如果启用了“服务异常时阻断网页请求”，引擎停止或令牌失效时网页请求会被拦截，这是保护行为。

## 6. 安全边界

- 脱敏与还原在本地完成；不要把真实密钥写入 Issue、截图、示例配置或文档。
- 关闭 Fail-Closed、启用明文直连或关闭扩展阻断都会改变保护边界，修改后应重新发送测试请求并检查日志。
- 修改配置后以面板状态和实际日志为准，不要只根据配置文件内容判断已经生效。
